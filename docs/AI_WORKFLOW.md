# AI 编程工作流

用结构化诊断定位错误，修改后重新检查、构建并运行：

```text
生成代码 → zam check --json → 读取 code/category/location/suggestion
→ 做最小修改 → zam fmt → 再 check → build → run
```

## 诊断契约

`check --json` 和 `build --json` 的 `diagnostics` 保留人类可读的 `message`，并提供稳定的 `code`、`category`、`file`、`line`、`column`、`function` 与可选 `suggestion`。AI 工具应优先依赖 `code` 和位置，不要用完整 message 做唯一分支条件。`zam/tests/diagnostics.rs` 用真实源码逐个断言这里的 code、category 和非空 suggestion（`ZM999` 没有可操作建议，是唯一的例外），避免分类只在单元测试里成立。

`check --json` 与 `build --json` 各输出一行 JSON，形状固定为 `{"command":...,"ok":...,"diagnostics":[...]}`：`ok` 是布尔值，`diagnostics` 是数组，按文件、行、列排序。词法、语法与模块解析错误遇到第一条就停，数组只有一项；通过这一步后，类型与所有权检查逐个函数独立进行，**每个出错的函数各报它的第一条错误**，所以数组可能有多项。AI 可以在一轮里修完各函数的问题再检查；同一函数里后续的错误要等第一条修好后才会出现。`file`、`line`、`column`、`function`、`suggestion` 都可能是 `null`（部分整项目级工具错误仍没有行列位置，`ZM999` 没有建议；可定位的导入错误会保留源位置）。失败时进程退出码为 1，stderr 仍有人类可读的诊断（格式见下），stdout 保持是合法 JSON。

不带 `--json` 时，有位置的诊断在 stderr 渲染成：

```text
error[ZM301]: use after move: name
 --> src/main.zm:8:5
  |
8 |     println(name)
  |     ^^^^^^^^^^^^^
  = help: borrow the value or move it only after the last use
```

词法与语法错误只划出出错的记号，语义错误从语句起点划到行尾。多条诊断之间空一行，最后一行是 `zam: N errors`。没有位置的错误仍是一行 `zam: <信息>`。解析这类文本不稳定，工具请用 `--json`。

常见代码包括：

- `ZM100`：词法字符错误；
- `ZM101`：字符串转义不支持；
- `ZM110`：语法结构错误；
- `ZM200`：类型不匹配；
- `ZM201`：名称未定义（变量、函数、结构体、类型名或枚举变体）；
- `ZM202`：结构体字段未定义；
- `ZM203`：调用或结构体的导入缺失、导入别名歧义（包括标准库与自定义模块）；检查对应 `use`，缺失则添加，同名别名冲突则消除歧义；
- `ZM204`：重复声明（导入、字段、函数或初始化项）；
- `ZM301`：移动后使用；
- `ZM302`：修改不可变绑定；
- `ZM406`：数组边界错误；
- `ZM421`：借用冲突；
- `ZM422`：借用逃逸；
- `ZM423`：借用类型不匹配；
- `ZM424`：不可变值的可变借用；
- `ZM425`：需要显式借用（缺少 `&` 或 `&mut`）；
- `ZM500`：未处理的可失败调用；
- `ZM509`：错误类型不是字符串、结构体或枚举（比如 `!i64`）；
- `ZM510`：缺失返回值；
- `ZM511`：`match` 没有覆盖枚举的所有变体，或 `_` 之后还有分支；为缺的变体补分支，或在最后加 `_:` 分支；
- `ZM600`：整数算术安全错误，包括字面量超出 `i64` 范围；
- `ZM900`：暂不支持的能力；
- `ZM999`：兜底分类，正常不该出现：反例里任何一条落到这里都说明该补一条分类（`zam/tests/diagnostics.rs` 断言不出现），AI 遇到时保留完整 `message` 并提交最小复现。

## 模板

使用 `zam new demo --template ai` 生成带 `.claude/skills/zamak/SKILL.md` 与 `AGENTS.md` 的项目（内容相同：工作循环加一页纸语言参考）。每轮只做一个局部修复；修复后重新运行 `check --json`，通过后再构建和执行。模板写明代码块靠缩进、用 `elif` 和 `and`/`or`/`not`、结构体字面量的写法，泛型与 `Option[T]`、函数值与匿名函数的写法，当前不支持的网络 I/O 和线程，以及 `i64` 与 `f64` 之间要显式转换，减少模型凭经验猜测语法的失败。缩进相关的报错（`expected an indented block`、`unexpected indent`、`unindent does not match any outer indentation level`、Tab 缩进）都归 `ZM110`，建议里给出具体改法；Tab 缩进先运行 `zam fmt`。

## 离线评测

`bench/ai/` 提供固定候选与固定补丁，不需要模型或网络。当前 29 个案例覆盖合法对照（单文件与多模块各一）、词法（含不支持的字符串转义）、语法（语句间缺少换行或未终止字符串）、类型、名称解析、缺少标准库导入、重复声明、所有权移动、修改不可变绑定、数组越界、借用冲突与借用逃逸、错误值处理、缺少字符串返回值、字面量超出 `i64`、未知结构体字段，以及一个应被拒绝的不支持能力负向对照。多模块案例用 `files` 字段给出多文件项目，脚本生成 `zam.toml` 与 `src/` 并以项目目录为检查/构建目标，覆盖跨模块 `use`、`pub fn` 与项目模式诊断。六个案例还用 `expected_location` 核对具体源文件及行列位置，覆盖缺少标准库导入、跨模块借用、单层/嵌套 `catch`、结构体导入缺失和别名歧义；首次与后续检查样本都必须匹配，位置错误会使整体验收失败。报告保留期望/实际位置、每次匹配结果和单独的位置匹配率，未声明位置的案例不计入该指标。评测记录首次检查通过率、一轮固定补丁的修复结果、每次 `check --json` 延迟、首次与缓存命中构建时间及产物大小。报告用 `zamak_backend` 记录本次所用的 C 后端（取 `CC` 环境变量，未设置即 Windows 默认 MSVC），使这些延迟数字自述后端，不与其它后端的批次混排。通过检查的案例还要构建、执行并核对输出；不支持的能力作为应被拒绝的对照例单独统计。它衡量工具链的反馈与验证流程，不代表任意模型的生成能力。
