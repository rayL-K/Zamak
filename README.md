# Zamak

一个适合AI时代使用的超级缝合怪语言

<img width="1254" height="1254" alt="Zamak" src="ico/Zamak.png" />

Zamak 是为频繁构建、多 worktree 协作设计的语言原型。当前 `zam` 支持多模块构建缓存、独立原生可执行文件，以及 `string` 的所有权和调用帧借用检查。原生后端先生成 C，再调用 MSVC（Windows）或 `cc`（Unix）生成机器码；安全语义由 Zamak 检查，用户程序不经过 Rust 编译器。

## 定位

- **要解决的痛点**：频繁构建的开发循环。模块级缓存让同一份源码在不同目录和工作树之间共享模块产物，热构建只重编译改动模块（本机两模块示例实测全命中约 262 ms，仅两次样本，未做多轮统计，也没有旧后端同机基线）。
- **目标用户**：写系统层代码、但不想承担复杂构建与长编译的人。语法目标是接近 Python 的阅读体验，同时在需要时能约束内存——目前约束只覆盖 `string` 的所有权与调用帧借用。
- **技术路线**：静态类型，编译成原生可执行文件。后端先生成 C，再由 MSVC（Windows）或 `cc`（Unix）编译链接；不做解释器，也不依赖 LLVM。安全语义和缓存都由 Zamak 自己实现，用户程序不经过 Rust 编译器。

### 生态现状

如实标注：只有 `check`、`build`、`run`、`demo` 四个子命令。标准库停在起步阶段（`std/string` 的 `byte_len`/`equal`，`std/io`、`std/fmt` 的 `println`）；没有包管理器、调试器、REPL、IDE 插件和文档生成；错误值、格式化、安装/发行流程尚未提供；泛型、闭包、枚举、match、线程和 unsafe/FFI 都还没有。因此当前只适合作为原型和小规模示例，不适合生产使用。

## 快速运行

首次从本地源码安装（无需发布到包注册表），在仓库根目录执行：

```powershell
cargo install --path zam --locked
```

安装目录需在 PATH 中；本机已配置。修改工具源码后，重新执行上述安装命令更新。日常使用直接执行：

```powershell
zam check examples/hello
zam build examples/hello
zam run examples/hello
zam demo
```

进入项目目录后可以省略路径，例如在 `examples/hello` 中执行 `zam run`。

运行示例输出：

```text
hello from zamak
你好，Zamak
```

`build` 输出 `OUTPUT <path>`，Windows 上是 `build/<name>-<hash>.exe`，Unix 上是同名的无后缀可执行文件，可以直接启动，也可用 `zam run <path>` 执行。产物不需要安装 Zamak 或 Rust；Windows 静态链接 C 运行库。命令失败返回非零退出码，错误写入 stderr。词法/语法错误包含源码文件、行号与列号；列号从 1 开始，按 Unicode 字符计数，制表符算一个字符，EOF 使用末尾位置。词法错误指向 token 起点，语法错误指向解析器发现错误的位置。语义错误包含行号、列号与所属函数，位置取当前语句的起点（`missing string return value` 取函数声明处）；因为一个模块对应一个文件，函数前面的模块名即可定位文件。没有路径参数时使用当前目录；源码后缀统一为 `.zm`；可以直接检查或构建单个源码文件。

Windows 构建需要 Visual Studio C++ 工具，自动通过 `vswhere` 查找 x64 MSVC。本机已安装。Unix 后端调用 `cc`，可通过 `CC` 指定编译器程序；已在 Ubuntu 26.04 + gcc 15.2 上实机验证构建、执行和全部集成回归。`check` 不需要 C 编译器。旧 `.zbc` 产物已不再支持，需要重新构建。

## 项目配置

```toml
[project]
name = "hello"
entry = "src/main.zm"
modules = "src"
```

配置必须只有 `[project]` 和上述三个字符串字段；路径相对配置文件，不能包含 `..`，入口必须在模块目录内。工具递归扫描模块目录里的 `.zm` 文件；一个文件对应一个模块，例如 `src/tools/greeting.zm` 的模块名是 `tools/greeting`。暂不支持源码符号链接。

```zam
use tools/greeting
use std/io

fn main() {
    greeting.hello()
    io.println("你好")
}
```

被导入模块里的函数必须声明为 `pub fn`。导入使用 `/`，调用使用模块路径的末段名称；有歧义的模块别名、缺失模块、私有函数调用、重复声明和模块依赖环都会报错。

## 当前语法范围

- `fn`、`pub fn`，带类型的参数：`string`、`&string`、`&mut string`、`i64`、`bool`。返回值支持 `string`、`i64`、`bool`，或省略表示无返回值。
- `let name = expr`、`let mut name = expr`、可选类型标注，以及可变绑定的重新赋值。整数和布尔值复制，字符串移动。
- 十进制整数允许在数字之间使用单个 `_` 分隔符（如 `1_000_000`），首尾或连续分隔符会报错。整数算术 `+ - * / %`、比较 `== != < <= > >=`、布尔相等比较、单目 `- !` 和括号。表达式与参数从左到右求值；溢出、除零及 `i64::MIN / -1` 在运行时返回错误。
- 本地/导入函数调用、嵌套调用、`return`；最后一个值表达式可作为返回值。
- `println(expr)` 打印字符串、整数或布尔值；打印变量时不移动变量。导入 `std/io` 或 `std/fmt` 后可使用相应的命名空间。
- 导入 `std/string` 后可用 `string.byte_len(&text) -> i64` 查询 UTF-8 字节数，`string.char_len(&text) -> i64` 按 UTF-8 码点计数（一个汉字算一个字符，续字节不计）；`string.equal(&a, &b) -> bool` 按字节比较内容，支持重复共享借用，不移动字符串；共享借用参数可直接转传。当前要求共享借用，不接受字面量、owned 参数或可变借用。示例：`zam run examples/values/strings.zm`。
- 字符串支持 UTF-8，以及 `\n`、`\r`、`\t`、`\"` 和 `\\` 转义。
- 字符串字面量支持插值：`"{name}"` 拼接当前作用域里的变量或字段（`{person.name}`），支持 `string`、`i64`、`bool`。插值只读取不移动，插值后原变量仍可使用；字面大括号写作 `{{` 和 `}}`。花括号内目前只支持变量与字段路径，暂不支持调用、字面量和借用。示例：`zam run examples/values/format.zm`。
- `if condition { ... } else { ... }`、`while condition { ... }`，条件必须是 `bool`；支持 `&&`/`||` 短路求值。块内变量不能逃出块；支持 `else if` 链，复用嵌套分支的返回与所有权路径合并。支持 `break`/`continue`，跳转后同一代码块中的语句不可达，嵌套循环只影响当前循环；暂不支持遮蔽仍在作用域内的绑定。
- `struct` / `pub struct`，名称首字母大写，字段支持 `string`、`i64`、`bool` 和 owned 命名结构体，每行一个字段。用 `Person { ... }` 或 `model.Person { ... }` 按名初始化全部字段，读取整数/布尔字段，也可直接打印字符串字段（不移动）。支持可变结构体字段赋值、整体移动、整体重新赋值和字符串字段自动释放；替换字符串字段会先计算新值，再释放旧值。重复/缺失字段、借用字段和移动后使用会报错。支持 owned 结构体函数参数、返回值和变量类型标注（跨模块用 `model.Person`）；传参及返回转移整体所有权，未使用的返回值会自动释放。嵌套 owned 结构体支持构造、字段整体替换及递归释放；直接/间接递归布局会报错。支持连续字段访问（如 `a.b.c`）：读取标量、非移动打印字符串、替换可变根绑定下的字段；路径上的每一层均检查类型、字段名称和根绑定有效性。字符串字段支持调用帧借用（如 `&person.name`、`&mut person.name`，可嵌套），独占借用要求根绑定可变。冲突保守地按根结构体检查，不允许同时独占借用不同字段；借用字段时不能移动根结构体。暂不支持单独移出 owned 字段和整体结构体借用。示例：`zam run examples/structs`。
- 换行分隔语句；支持 `#` 和 `//` 单行注释。

### 所有权与借用

```zam
fn show(s: &string) { println(s) }
fn change(s: &mut string) { s = "changed" }
fn consume(s: string) { println(s) }
fn main() {
    let mut a = "hello"
    show(&a)
    change(&mut a)
    let b = a
    consume(b)
}
```

赋值和 owned 参数传递移动字符串；移动后使用会在 `check` 阶段报错。可变变量可以重新初始化。借用只能作为参数，调用返回即结束；共享借用允许多个，可变借用必须独占，且要求可变所有者。同一次调用中借用和移动同一变量会报错，嵌套调用也遵守外层已开始的借用。借用参数可以继续传给下层调用，但不能移动、返回或存进本地变量。字符串通过显式分配和作用域结束时的释放管理，不使用 GC/引用计数。

运行 `zam run examples/ownership` 查看完整示例。分支之后只允许使用所有继续路径都有效的字符串；返回分支不参与合并。循环回到下一轮前必须重新初始化已移动的外层字符串。检查保守地分析所有分支，不利用常量条件排除路径。`zam run examples/control/main.zm` 演示阶乘、GCD 和循环移动后重初始化；`zam run examples/control/jumps.zm` 演示嵌套循环中 `continue` 只跳到当前循环下一轮、`break` 只退出当前循环。`break`/`continue` 后同一代码块中的语句不可达，会在检查阶段报错。支持定长 `[i64; N]` 数组字面量、整数索引、可变元素赋值和运行时边界检查；长度限制为 1–1024。不支持动态数组、其他元素类型或数组移动借用。当前尚不包含泛型、闭包、线程、unsafe 或 FFI，因此不能宣称已实现完整 Rust 级内存安全。原生程序没有解释器的步数限制；无限递归可能耗尽栈。

## 缓存行为

缓存默认放在用户目录 `.zam/cache`，可用 `ZAMAK_CACHE_DIR` 指定。模块键包含源码字节、依赖名称与递归依赖哈希、Zamak 编译器/IR 版本（当前 IR-10）、操作系统和架构，不含项目绝对路径。相同源码从不同目录构建共享模块产物。

修改依赖会使该模块和其传递依赖方失效，独立模块继续命中缓存。当前仍对全部源码执行解析和检查，并比较缓存产物内容；缓存验证以正确性为优先，尚未实现只读接口的语义增量分析，也没有宣称达到设计文档的性能指标。

缓存发布过程为：同目录独占创建临时文件，写入并同步后，通过硬链接原子发布最终文件。并发构建可以重复计算，但同一缓存键只保留一个完整产物；不同内容或损坏缓存会报错。缓存所在文件系统必须支持硬链接。正常执行会清理临时文件；进程被强制终止可能留下 `.tmp` 文件。缓存清理和容量限制尚未提供子命令。

模块缓存保存确定性的 IR；原生后端为每个模块生成独立 C 和目标文件。目标文件键包含模块生成的 C（实现、实际调用函数的接口声明，以及本模块函数实际构造或实际使用函数签名中的结构体布局）、平台、架构、编译选项和本机工具链身份。无关结构体布局变更不改变目标文件或链接键；已使用布局变更会重新检查并使使用模块失效。仅修改被调用函数的实现时，调用方目标文件继续命中；修改实际使用的接口时，调用方失效或在类型检查阶段报错。函数符号由完整模块/函数名称稳定编码，增加无关函数不改变已有符号。

Windows 编译使用 `/Brepro` 与 `/d2pathmap` 将临时目录映射为固定路径，避免同一键的目标文件因构建目录不同而产生不同字节；并发回归会校验该条件。

链接键包含按模块排序的目标文件键、工具链身份和链接选项。目标文件与可执行文件都有 SHA-256 校验；输出分别显示 `OBJECT HIT/MISS` 和 `LINK HIT/MISS`。项目产物同样按内容命名和原子发布。IR 缓存仍使用递归源码依赖键，尚未实现语义检查缓存。`check` 不写缓存或构建产物。

## 验证

```powershell
cargo test --manifest-path zam/Cargo.toml
cargo clippy --manifest-path zam/Cargo.toml --all-targets -- -D warnings
```

集成检查覆盖跨目录缓存复用、原生产物一致性、独立执行、中文输出、依赖变更和独立模块命中、四个进程共享冷缓存、缓存损坏、语法错误、可见性、依赖环和配置路径校验。另覆盖字符串移动、借用修改、返回、重新初始化、重复共享借用，以及移动后使用、借用冲突/逃逸、错误参数和不可变赋值等反例；字符串插值覆盖中文字面量、整数/布尔/字段读取、非移动读取，以及未闭合、嵌套、未知变量和移动后使用等拒绝；诊断覆盖词法/语法错误的文件与行列，以及语义错误的行列与函数定位。

当前实现只是语言草案的一部分，多数功能还未实现；已在文档中标注的能力之外，语法与库都可能变化。
